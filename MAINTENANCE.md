# Maintenance guide — Shore Town Guide

All content lives in `data/`. `build.py` turns it into the static site in `docs/`.
`docs/` is build output: it is git-ignored and GitHub Actions rebuilds it on every push to `main`.

| File | What it holds |
|---|---|
| `data/towns.json` | 55 towns, their facts (each with source URL, tier, last-checked date), status |
| `data/events.json` | Generated by `scripts/fetch_events.py` — do not edit by hand |
| `data/events_manual.json` | Hand-checked events from official pages that can't be fetched automatically |
| `data/site.json` | Site name, tagline, off-season note, sponsor placeholder text |
| `data/places_seed.json` | Curated things-to-do list: `[name, town slug, category, wikipedia title or null, optional OSM query]` |
| `data/places_links.json` | Hand-checked official URLs that override OSM/Wikidata links |
| `data/places.json` | Generated by `scripts/enrich_places.py` (do not edit by hand) |
| `data/realestate.json` | Generated by `scripts/realestate_data.py`: ACS median value, NJ tax rates, ratios, FEMA/search links |
| `data/cache/*.json` | Nominatim + Wikipedia caches. **Commit them**: they keep us inside the Nominatim usage policy |

## Weekly: refresh events (≈10 minutes, Thursday or Friday)

```bash
python3 scripts/fetch_events.py     # pulls official + tourism calendars, 60-day window
python3 build.py                    # rebuilds docs/
python3 -m http.server 8000 -d docs # look at / and /events/
git add data && git commit -m "Weekly events refresh $(date +%F)"
```

* The fetch prints a per-source report. If a source fails, its last good events are kept
  (marked stale in `data/events.json` → `sources`) so the site never goes blank.
* Meetings, closures and trash/recycling notices are dropped by the `EXCLUDE` regex in
  `scripts/fetch_events.py`. Adjust it if a real public event gets filtered out or noise gets in.
* **Linwood** (`linwoodcity.org`) often times out from scripts. Check
  <http://www.linwoodcity.org/> → Events in a browser and copy events into
  `data/events_manual.json` (`town`, `title`, `date`, `time`, `location`, `url`, `source_url`, `checked`).
  Delete manual entries once they're in the past.
* **Sea Isle City and Cape May** calendar pages returned HTTP 500 in Oct 2026. Re-try them;
  if they work, add them to `SOURCES`.
* Adding a feed: add an entry to `SOURCES` in `scripts/fetch_events.py`. Supported types:
  `tribe` (WordPress "The Events Calendar": `/wp-json/tribe/events/v1/events`),
  `evogov` (`/meetings/get_list?selected_calendar_ids=…` — find ids by opening the calendar
  with browser dev tools → Network), `civicplus_rss` (`/RSSFeed.aspx?ModID=58&CID=All-calendar.xml`),
  `linwood_asp`. Only use **official** town or tourism-bureau calendars.
* Current sources: town calendars (Brigantine, Stone Harbor, Upper Twp, Ocean City, Ventnor, Margate,
  Linwood, Visit Somers Point), OC Regional Chamber (oceancityvacation.com), Ocean County Tourism
  (oceancountytourism.com, capped at 8 pages) and the Wildwoods tourism calendar (wildwoodsnj.com).
  Not used: Facebook (never scraped; link an official page with a town's `facebook_url` field for a
  "More on Facebook" button), Eventbrite (no scraping), Simpleview-powered tourism sites
  (visitatlanticcity.com, Cape May County) because events only come through an internal token API.
  The site owner can send events by hand. Add them to `data/events_manual.json` with the official source URL.
* Event coordinates use the venue's lat/lon when the feed provides it, otherwise the town centre
  (`data/towns.json` → `geo`). Cards say "distance from town centre" in that case.
* The GitHub Actions workflow also re-fetches events on its weekly schedule when deployed.
  It does not commit the result, so still commit `data/events.json` after a local refresh (pushing to `main` redeploys).

## Each spring (March–May): badge prices and summer rules

Towns post new prices between January and May, and preseason discounts usually end in May or June.

1. In `data/towns.json` set top-level `badge_year` (and each town's `badge_year`) to the new year.
   Update the `season_note` in `data/site.json`.
2. For every town, open the `source` URL of each fact and re-check:
   `badge`, `prices` (daily / weekly / seasonal / preseason), `where_to_buy`, `free_beach`,
   `lifeguards`, `dogs`, `alcohol`, `parking`, `boardwalk`.
   Update `value`, `detail` and set `checked` to today's date. If a page disappeared, find the
   new official page; if you can't, **delete the fact** (the site shows "Not yet verified")
   rather than keep a stale one.
3. Update `compare` (`seasonal`, `daily`, `free_beach`, `dogs_summer`, `dogs_offseason`) to match.
4. Source tiers: `official` (town site, municipal code on eCode360, county) >
   `tourism` (official tourism bureau) > `news` (only for `*_reported` fields, shown with a warning).
   Never fill a fact from memory or an unofficial site.
5. Set each town's `status` (and `coverage` note) in `data/towns.json` by these rules: **verified** = badge, free_beach, lifeguards, dogs and
   alcohol all from official/tourism sources; **partial** = some; **reported** = only news;
   **stub** = nothing. Promote stubs by adding official facts.
6. Re-check the known discrepancies noted on town pages (Stone Harbor daily $10 vs $8,
   Ventnor dog hours, Wildwood dog-beach location, Longport weekly price, Wildwood Crest
   off-season dogs, Strathmere's first paid season in 2027).
7. `python3 build.py`, look over `/compare/`, commit.

## Before each summer (Memorial Day)

* Check lifeguard start dates, dog-beach hours and parking-meter rates/apps (they change often).
* Re-check that the free beaches (Atlantic City, the Wildwoods, …) are still free.

## Things to do (places)

```bash
python3 scripts/geocode_towns.py    # only for new towns (cached; 1 req/sec; custom User-Agent)
python3 scripts/geocode_places.py   # verifies each seed against OpenStreetMap via Nominatim (cached)
python3 scripts/enrich_places.py    # descriptions from Wikipedia / official site meta, official links
```

* Add a place by appending a row to `data/places_seed.json`. Never add a place you can't find on
  OpenStreetMap or an official site. A place is kept only if its OSM match lies within 9 mi of the town.
* Places with no quotable description say "No description verified yet". Descriptions are short quotes
  with their source linked.
* Restaurants and bars: add only with an official or verifiable public source.

## Each year: real-estate snapshot

* **ACS**: when a new 5-year release comes out (December), update `ACS_RELEASE` in
  `scripts/realestate_data.py` (via the Census Reporter API; no key needed).
* **Tax rates** (published ~spring): download the new General & Effective Tax Rates PDF to
  `research/nj_<year>taxrates.pdf`, `pdftotext -layout` it to `.txt`, and update the paths in the script.
* **Ratios**: use the Table of Equalized Valuations certified the *previous* October (for tax year N, use the
  (N-1) TEV). Effective rates in the state PDF can differ from general × ratio when a town revalued
  (e.g. Seaside Heights 2025). We publish the state's numbers as printed.
* Rental registration: only Ocean City's is verified on the checklist. Add others with an official link.

## Ask Google AI box

The header/home box opens `https://www.google.com/search?udm=50&q=<query> South Jersey shore` in a new tab.
`udm=50` is Google's AI Mode parameter (observed, not formally documented). If it stops working,
remove the hidden `udm` input in `ask_ai()` in `build.py` and the `udm=50&` in `src/app.js`
to fall back to a normal Google search.
